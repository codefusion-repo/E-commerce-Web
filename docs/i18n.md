# Frontend i18n

Spanish is the default and fallback language. English is the secondary language.

## Strategy

- The app keeps the existing route structure. There are no `/es` or `/en` route prefixes.
- The active locale is stored in a non-sensitive cookie (`cf_locale`) and localStorage key (`codefusion-demo-locale`).
- Server rendering reads the cookie to set `<html lang>` and root metadata when a preference already exists.
- Client rendering updates `<html lang>`, visible UI text, accessible labels, and runtime metadata after language changes.
- Unknown server, catalog, blog, or user-generated content falls back to the original Spanish/source text.

Full locale routing was intentionally not added because the current app uses many existing public, checkout, receive, auth, profile, cart, and catalog routes. Rewriting those routes for this issue would be a higher-risk routing change and could affect checkout, Flow return paths, auth redirects, cart state, and SEO canonicals.

## Files

- `client/src/i18n/config.ts`: supported locales, cookie/storage keys, `html lang`, and metadata copy.
- `client/src/i18n/dictionaries.ts`: reviewed phrase dictionaries. Add exact Spanish-to-English entries here for fixed UI copy.
- `client/src/i18n/client.tsx`: provider, hook, persistence, runtime translation, and metadata updates.
- `client/src/components/i18n/languageSelector.tsx`: global language selector used by shared headers.

## Adding Copy

1. Keep Spanish as the source/default copy in components.
2. Add the English phrase to `SPANISH_TO_ENGLISH` for fixed UI text.
3. Add template handling in `translateTemplates` only when the copy includes safe dynamic values such as counts, codes, dates, or labels.
4. Do not add translations for secrets, private data, credentials, or arbitrary user-generated content.
5. If backend content needs first-class localized fields later, version that as a backend/content issue with migrations or seed updates.
